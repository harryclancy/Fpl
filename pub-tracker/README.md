# Dublin Pub Tracker

A private checklist, map, and pint journal for Harry & Ava to work their way through the pubs of Dublin.

No login, no backend, no API keys — everything runs client-side and is stored on-device.

## Stack

- **React 19 + TypeScript + Vite**
- **Tailwind CSS v4** for styling
- **React Router** for navigation
- **Leaflet + react-leaflet + leaflet.markercluster** for the interactive map (OpenStreetMap tiles — no Google Maps API key)
- **Dexie (IndexedDB)** for all user data: visited status, ratings, reviews, visits, drinks, photos, favourites, want-to-visit, saved crawls
- **vite-plugin-pwa** for installable/offline support

## Pub data

`src/data/pubs.json` (447 pubs) is generated by `scripts/build-pubs.mjs` from a real, open,
OpenStreetMap-derived community dataset of Dublin pubs (`scripts/raw-dublin-pubs.geojson`).
Area/postal-district are a best-effort nearest-centroid approximation (`scripts/dublin-areas.mjs`)
that users can correct per-pub in the app via **Edit Pub Details**.

To refresh/regenerate the dataset later:

```bash
node scripts/build-pubs.mjs
```

Swap in a different/updated `raw-dublin-pubs.geojson` (e.g. a fresh Overpass API export in the same
`{name, lat, lon}` shape) to expand coverage without touching app code.

## Development

```bash
npm install
npm run dev      # dev server
npm run build    # production build (type-checks then builds)
npm run preview  # preview the production build
```

## Data & privacy

- All user data (visits, reviews, photos, favourites, crawls) lives in the browser's IndexedDB.
- **Settings → Export Backup / Import Backup** lets you back up or transfer that data as a single JSON file — do this before switching devices, since there's no account/cloud sync.
